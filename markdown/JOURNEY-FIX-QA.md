# แก้เส้นทางเมนเทอร์และการจอง — 14 กันยายน 2026

## สิ่งที่แก้

- เปิดคิวโดยตีความค่าที่กรอกเป็นเวลาไทย +07:00 เสมอ แม้เครื่องอยู่เขตเวลาอื่น ไม่ล้างค่าที่เลือกเมื่อส่งคำขอไม่สำเร็จ
- แสดงข้อความแนะนำทีมในนัดของฉันก่อนเมนเทอร์รับ/ปฏิเสธ รักษาบรรทัดและตัดคำยาวให้พอดีจอ
- เมื่อเมนเทอร์ไม่ตรงกับงานหรือเลือกไม่รับงานนั้น หน้าสาธารณะแสดงเหตุผลและลิงก์กลับไปเลือกใหม่ ไม่ให้กรอกฟอร์มจองที่ส่งไม่ได้
- ปักวันเวลาไทย สถานะ งานแข่งขัน และโจทย์ของนัดในแชต พร้อมเปิดดูนัดอื่น/ประวัติเดิม สมาชิกในห้องอ่านได้ ผู้ที่ไม่ได้เป็นสมาชิกอ่านไม่ได้
- รับคำขอจองตรวจเวลาทับซ้อนกับทั้งคำขอที่ยังไม่หมดอายุและนัดยืนยันแล้ว แม้เป็นคนละ slot ID เพื่อรองรับข้อมูลเก่าที่อาจทับกัน
- การบันทึก match audit ล็อก parent ด้วย key-share ภายใน transaction และข้ามเมื่อ parent ถูกลบไปแล้ว ป้องกัน foreign-key race ที่พบใน review
- ตัวรัน test ล้าง `RESEND_API_KEY` และ `BLOB_READ_WRITE_TOKEN` ก่อนเริ่ม subprocess เพื่อไม่ให้ทดสอบโดยใช้บริการส่งอีเมล/เก็บไฟล์จริงจาก `.env.local`

## Regression tests ที่เพิ่ม

- สองทีมขอ slot เดียวกันพร้อมกัน: สำเร็จเพียงหนึ่งทีม
- เจ้าของทีมเดียวมีคำขอรอยืนยันต่อ mentor/งานได้เพียงหนึ่งรายการ
- เปิดคิวทับซ้อนถูกปฏิเสธ และปิดช่องที่มีนัด/คำขออยู่ไม่ได้
- คำขอหมดอายุครบ 24 ชั่วโมง หรือถึงเวลาเริ่ม แล้วรับไม่ได้และปล่อยคิวตามกติกาโดยไม่รอ Cron
- รับคำขอพร้อมกันสองครั้งได้ห้องเดียวกัน
- ข้อมูลคิวเก่าที่ทับนัดเดิมขอจองไม่ได้ และคำขอเก่าที่ทับนัดยืนยันรับไม่ได้
- ยกเลิกแล้วจองใหม่ใช้ห้องเดิมพร้อมเก็บประวัติ/โจทย์ของแต่ละนัด
- แปลงเวลาไทยบน browser timezone UTC, Asia/Bangkok และ America/New_York
- แสดงโจทย์ก่อนรับนัด ปิดฟอร์มเมื่อไม่มี match และใช้คีย์บอร์ดเปิดประวัตินัด
- ตรวจคะแนนหลักฐาน 6 + ยืนยัน 3 + คำสำคัญ 2 + 2, จำกัดคำซ้ำ, ปิดหมวด และคำนวณซ้ำได้เหมือนเดิม
- ตรวจ axe และหน้าล้นที่ 390/768/1440px พร้อมภาพจริง `artifacts/journey-fixed-*.png`

## ขอบเขตการส่งมอบ

ไม่เพิ่ม migration หรือเปลี่ยน schema ในรอบนี้ ใช้ฐาน test แยกจาก dev/prod ไม่มีการ deploy หรือเปลี่ยนฐาน Production งานชำระเงิน/คืนเงินและการเชื่อม provider จริงยังอยู่นอกขอบเขต

คำสั่งตรวจ: `npm.cmd test`, `npm.cmd run test:auth`, `npm.cmd run test:safety`, `npm.cmd run build`

## ผลตรวจ

- Full browser suite: **152 passed / 10 skipped** (3.4 นาที) ข้อที่ข้ามเป็นเงื่อนไขเดิมที่รันการเขียนข้อมูลบางกรณีเฉพาะ desktop
- หลังปรับ query คิวว่างให้ตัดช่วงเวลาที่ทับกัน รันทดสอบ booking races/expiry/overlap/cancellation/room reuse ซ้ำครบ desktop/tablet/mobile: **3 passed**
- Auth/Google callback จำลองและ profile API: **17 passed**; database safety: **5 passed**
- TypeScript และ Vite build รอบสุดท้ายผ่าน มีคำเตือนขนาด JavaScript หลักประมาณ 501 kB (gzip 142 kB) ซึ่งควรแยกโหลดตาม route ในงาน performance ต่อไป
- ตรวจภาพจริงของรายละเอียดนัดและประวัติที่ 390/768/1440px ไม่มีหน้าล้นในภาพและ viewport assertions ที่ตรวจ ผ่าน axe และการใช้คีย์บอร์ดเปิดประวัติ
- รอบ full suite หลังตัดคีย์ภายนอกไม่พบ API foreign-key error เดิมหรือ error จากการส่งอีเมล
