# เส้นทาง "อยากแข่งงานไหน" — เลือกเวที เจอเมนเทอร์ จองเวลา คุยในเว็บ

อัปเดต: 13 กันยายน 2569

เอกสารนี้อธิบายเส้นทางหลักที่มาแทนหน้าเลือกเมนเทอร์แบบเดิมที่เริ่มด้วยคำถาม "ทีมคุณกำลังติดตรงไหน"
ใช้คู่กับ [competition-model.md](competition-model.md) ที่ว่าด้วยหมวดหมู่ 13 หมวดเดิม
[chat.md](chat.md) ที่ว่าด้วยห้องแชต และ [backend.md](backend.md) ที่ว่าด้วย API ส่วนอื่น

## 1. เส้นทางใช้งาน

```
/explore  →  /competitions/:slug  →  /mentors/:id?competition=:slug  →  /profile  →  /chats/:id
เลือกเวที     ดูงานและเมนเทอร์ที่ว่าง     ขอจอง 60 นาที               เมนเทอร์กดรับ     คุยกันในเว็บ
```

- ไม่มีการนัดผ่าน Google Meet หรือ Zoom การปรึกษาทั้งหมดอยู่ในแชตของเว็บ
- รอบนี้ยังไม่เก็บเงิน ใบสมัครเมนเทอร์จึงไม่มีช่องราคาและคิวเสียเงิน
- ทางเข้า "สมัครเป็นเมนเทอร์" อยู่ในหน้า `/profile` ไม่ใช่หน้าเมนเทอร์รวมอีกต่อไป
- `/mentors` เดิมเปลี่ยนทางไป `/explore` ส่วนลิงก์เก่าที่มี `?competition=` ไปที่หน้าเวทีนั้น

## 2. ประเภทงานและหมวด แยกจาก taxonomy เดิม

`kind` และ `themes` เป็นแกนใหม่ อยู่คนละชุดกับหมวดหมู่ 13 หมวดเดิมโดยตั้งใจ
หมวดเดิมยังใช้กับสีปก ป้ายบนการ์ด และการค้นหา ส่วนสองช่องนี้ใช้กับหน้าสำรวจและการจับคู่เมนเทอร์

| ช่อง | ค่า |
|---|---|
| `kind` | `hackathon`, `case_competition` |
| `themes` | `innovation`, `business`, `education`, `medical` (เลือกได้หลายค่า) |

ค่าทั้งสองอยู่ที่ [src/data/focus.ts](../src/data/focus.ts) ไฟล์เดียว ทั้งหน้าเว็บและเซิร์ฟเวอร์นำเข้าจากที่นี่
จึงไม่มีรายการซ้ำสองที่ให้หลุดกัน

**เวทีที่ยังไม่จัดประเภทจะไม่ขึ้นหน้า `/explore` และเปิดหน้ารายละเอียดไม่ได้**
เพราะ `listCompetitions` และ `findCompetitionBySlug` กรอง `kind is not null`
หน้า `/admin/listings` จึงบังคับกรอกสองช่องนี้ และขึ้นป้าย "ยังไม่จัดประเภท" ให้เวทีเก่าที่ยังขาด
ใบที่ผู้จัดส่งเข้ามาก็กรอกเองได้ ถ้าเป็นใบเก่าที่ยังไม่มี ผู้ตรวจต้องเติมให้หลังเผยแพร่

> ข้อควรระวังตอนเขียนคิวรี: `themes` เป็น `text[]` ห้ามเขียน `` sql`... && ${array}::text[]` ``
> เพราะไดรเวอร์จะส่งอาร์เรย์เป็นพารามิเตอร์เดียวแล้วคิวรีพัง ให้ใช้ `arrayOverlaps()` ของ drizzle

## 3. การจับคู่เมนเทอร์

คะแนนคำนวณแยกรายหมวดที่ `scoreThemes()` ใน [src/data/focus.ts](../src/data/focus.ts) เวอร์ชันกฎคือ `RULE_VERSION`

| หลักฐาน | คะแนนต่อหมวด |
|---|---:|
| ผลงานที่ผู้ตรวจยืนยันและระบุหมวดแล้ว | 6 |
| เมนเทอร์ยืนยันเองว่าถนัดหมวดนี้ | 3 |
| คำสำคัญในช่อง "ประสบการณ์" | คำละ 1 สูงสุด 2 |
| คำสำคัญในช่อง "ช่วยได้ดีที่สุด" | คำละ 1 สูงสุด 2 |

- ตั้งแต่ **3** ขึ้นไปถือว่าใช้จับคู่ได้ ต่ำกว่านั้นแสดงเป็นข้อเสนอให้เมนเทอร์ยืนยัน
- ไม่ใช้ข้อความในช่อง "ช่วยไม่ได้" มาคำนวณ
- เมนเทอร์ยืนยันหรือปิดหมวดเองได้ที่ `/profile` แต่ **แก้สถานะผลงานผ่านตรวจเองไม่ได้**
  ผู้ตรวจเป็นคนให้หมวดกับผลงานที่หน้า `/admin/mentors/:id`
- ไม่มีการเรียก AI ภายนอก และไม่มีป้ายอันดับความนิยมหรือเปอร์เซ็นต์ความแม่นยำ
- ผลคะแนนบันทึกไว้ที่ `mentor_match_audit` พร้อมเวอร์ชันกฎ เขียนเฉพาะตอนผลเปลี่ยน ไม่เขียนทุกครั้งที่อ่าน

### การเรียงลำดับเมนเทอร์ของเวทีหนึ่ง

กรองให้เหลือผู้ที่ผ่านอนุมัติ มีบัญชีเชื่อม มีช่องเวลาว่างในอนาคต และไม่ได้ระบุว่าไม่รับงานนี้ แล้วเรียงตาม

1. ผู้ที่เลือก "ช่วยงานนี้" โดยตรง
2. จำนวนหมวดที่ตรงกับงาน มากไปน้อย
3. คะแนนรวมของหมวดที่ตรง มากไปน้อย
4. ช่องเวลาว่างเร็วที่สุด แล้วใช้รหัสเมนเทอร์ตัดสินให้ลำดับคงที่

ถ้าไม่มีใครตรง หน้าเวทีจะบอกตามจริง ไม่เติมรายชื่อที่ไม่เกี่ยวข้องให้หน้าดูเต็ม

## 4. คิว การจอง และการเปิดห้องแชต

- เมนเทอร์เปิดช่องเวลาครั้งละ **60 นาที** ที่ `/profile` หน้าจอใช้เวลาไทย ฐานข้อมูลเก็บ UTC
- คำขอสถานะ `pending` กันช่องเวลานั้นไว้ทันที
- คำขอหมดอายุเมื่อครบ **24 ชั่วโมง** หรือถึงเวลาเริ่มนัด แล้วแต่ว่าอย่างใดถึงก่อน
- เมนเทอร์ต้องติ๊กยืนยันว่าไม่ได้เป็นกรรมการตัดสินทีมนี้ก่อนรับคำขอ ปฏิเสธต้องมีเหตุผล
- หนึ่งคำขอที่รอยืนยันต่อ เจ้าของทีม–เมนเทอร์–เวที เท่านั้น
- ทั้งสองฝ่ายยกเลิกก่อนเวลาเริ่มได้พร้อมเหตุผล การเลื่อนใช้วิธียกเลิกแล้วขอใหม่
- สถานะ: `pending` / `confirmed` / `declined` / `cancelled` / `expired` / `elapsed`
  โดย `elapsed` คือพ้นเวลานัด ไม่ใช่หลักฐานว่ามีการให้บริการครบแล้ว

การกันคิวชนกันทำที่เซิร์ฟเวอร์ด้วย transaction และ `SELECT ... FOR UPDATE` บนแถวเมนเทอร์
ทุกการเปลี่ยนสถานะจึงเข้าคิวทีละรายการต่อเมนเทอร์หนึ่งคน ไม่ได้อาศัยการซ่อนปุ่มบนหน้าเว็บ
และการหมดอายุอ่านจาก `clock_timestamp()` ของฐานข้อมูลทุกครั้ง ไม่พึ่ง Cron ให้ทำงานตรงนาที

เมื่อเมนเทอร์กดรับ ระบบจะสร้างหรือใช้ห้องแชตเดิมของ เจ้าของทีม–เมนเทอร์–เวที นั้น
**ไม่มี API สร้างห้องแชตโดยตรงอีกแล้ว** และไม่มี API ตั้งนัดคอลภายนอก

## 5. โปรไฟล์ของสมาชิก

ทางเข้าคือ **ชื่อผู้ใช้บนหัวเว็บ** ซึ่งเป็นลิงก์ไป `/profile` ส่วน `/profile/edit` คือหน้าแก้ไข

หน้า `/profile` เรียงจากของสมาชิกทั่วไปก่อน แล้วค่อยต่อด้วยเครื่องมือของเมนเทอร์

| บล็อก | มีอะไร | ใครเห็น |
|---|---|---|
| ข้อมูลของฉัน | รูปโปรไฟล์ ชื่อที่แสดง แนะนำตัว สถานะ ที่สังกัด ชั้นปีหรือตำแหน่ง ระดับการศึกษา | ทุกคนที่ล็อกอิน |
| บัญชีและความปลอดภัย | อีเมล สถานะรหัสผ่าน การผูก Google | ทุกคนที่ล็อกอิน |
| ใบสมัครเมนเทอร์ · นัดของฉัน | สถานะใบสมัคร และนัดทั้งหมดของทั้งสองฝั่ง | ทุกคนที่ล็อกอิน |
| ความถนัด · งานที่ช่วยได้ · คิว | เครื่องมือจับคู่และเปิดช่องเวลา | เฉพาะเมนเทอร์ที่อนุมัติแล้ว |

คำที่ใช้ในบล็อกแรกตรงกับใบสมัครเมนเทอร์ (สถานะ / ที่สังกัด / ชั้นปีหรือตำแหน่ง)
และระดับการศึกษาใช้ `levelEnum` ชุดเดียวกับระดับผู้เข้าแข่งของเวที เพื่อให้เทียบกันได้ในอนาคต
ตัวเลือกทั้งหมดอยู่ที่ [src/data/profile.ts](../src/data/profile.ts) ไฟล์เดียว ทั้งหน้าเว็บและเซิร์ฟเวอร์ใช้ร่วมกัน

ข้อกำหนดที่บังคับฝั่งเซิร์ฟเวอร์:

- รูปโปรไฟล์ต้องเป็นไฟล์รูปที่ **ผู้ใช้คนนั้นอัปโหลดเอง** ผ่าน `POST /api/files` เอา id ของคนอื่นมาใส่ไม่ได้
- เปลี่ยนอีเมลต้องกรอกรหัสผ่านปัจจุบัน และล้าง `emailVerifiedAt` เสมอ
  เพราะอีเมลใหม่ยังไม่ผ่านการยืนยัน ห้ามสืบทอดสิทธิ์ของอีเมลเดิม
- บัญชีที่ผูก Google **เปลี่ยนอีเมลที่นี่ไม่ได้** ต้องไปเปลี่ยนที่บัญชี Google
  แต่ตั้งรหัสผ่านครั้งแรกได้โดยไม่ต้องกรอกรหัสเดิมที่ไม่เคยมี
- เปลี่ยนรหัสผ่านแล้วเตะ session อื่นออกทั้งหมด (`destroyAllSessions`) แล้วออกคุกกี้ใหม่ให้เครื่องที่เพิ่งเปลี่ยน
- คำขอที่เปลี่ยนข้อมูลใต้ `/api/auth` ต้องมาจาก origin ของเว็บนี้ เหมือนที่ `/api/chats` กับ `/api/journey` ทำ

## 6. API

| Endpoint | สิทธิ์ | หน้าที่ |
|---|---|---|
| `GET /api/journey/competitions/:slug/mentors` | ทุกคน | เมนเทอร์ที่ตรงกับเวทีนี้และมีคิวว่าง |
| `GET /api/journey/mentors/:id` | ทุกคน | โปรไฟล์สาธารณะ ใส่ `?competition=` เพื่อดูเหตุผลการจับคู่ |
| `GET /api/journey/profile` | ผู้เข้าสู่ระบบ | บัญชี ใบสมัคร ความถนัด งานที่รับ คิว และนัดทั้งหมด |
| `POST /api/journey/profile/themes` | เมนเทอร์ที่อนุมัติแล้ว | ยืนยันหรือปิดหมวดของตัวเอง |
| `POST /api/journey/profile/choices` | เมนเทอร์ที่อนุมัติแล้ว | `help` / `exclude` / `auto` ต่อหนึ่งเวที |
| `POST /api/journey/profile/slots` | เมนเทอร์ที่อนุมัติแล้ว | เปิดช่องเวลา 60 นาที |
| `DELETE /api/journey/profile/slots/:id` | เมนเทอร์ที่อนุมัติแล้ว | ปิดช่องที่ยังไม่มีนัด |
| `POST /api/journey/bookings` | ผู้เข้าสู่ระบบ | ขอจอง |
| `POST /api/journey/bookings/:id/respond` | คู่กรณีของนัดนั้น | `accept` / `decline` / `cancel` |
| `POST /api/journey/awards/:id/verify` | ผู้ตรวจ | ให้หมวดกับผลงาน หรือถอนการยืนยัน |

โปรไฟล์ของตัวเองอยู่ใต้ `/api/auth` เพราะเป็นเรื่องของบัญชี ไม่ใช่เรื่องของเส้นทางหาเมนเทอร์

| Endpoint | สิทธิ์ | หน้าที่ |
|---|---|---|
| `PATCH /api/auth/profile` | ผู้เข้าสู่ระบบ | บันทึกทั้งบล็อกข้อมูลส่วนตัว ส่ง `avatarFileId` เป็น null เพื่อเอารูปออก |
| `POST /api/auth/email` | ผู้เข้าสู่ระบบ | เปลี่ยนอีเมล ต้องกรอกรหัสผ่านปัจจุบัน |
| `POST /api/auth/password` | ผู้เข้าสู่ระบบ | ตั้งหรือเปลี่ยนรหัสผ่าน |

## 7. ตารางที่เพิ่มเข้ามา

`mentor_slots`, `bookings`, `booking_events`, `mentor_competition_choices`, `mentor_match_audit`
พร้อมคอลัมน์ใหม่ `competitions.kind` / `competitions.themes`,
`competition_submissions.kind` / `.themes`, `mentors.confirmed_themes` / `.disabled_themes`,
`mentor_awards.verified_themes` / `.verified_by` / `.verified_at` และ `chat_rooms.competition_id`

`mentor_submissions.price` / `paid_slot` / `free_slot` และ `mentors.price` เปลี่ยนเป็นค่าว่างได้
ข้อมูลเดิมยังอยู่ครบ ไม่ได้ใส่ราคาสมมติเพื่อให้ผ่าน validation

ส่วน `users.avatar_url` มีอยู่แล้วแต่เดิมมีแค่ Google ที่เขียน ตอนนี้ผู้ใช้ตั้งเองได้

migration อยู่ที่ `server/db/migrations/0002_neat_tag.sql` และ `0003_neat_drax.sql`
ต้องรันกับฐานของแต่ละสภาพแวดล้อมก่อนใช้งาน

## 8. ยังไม่ได้ทำในรอบนี้

- ระบบชำระเงิน คืนเงิน และจ่ายเงินให้เมนเทอร์
- อัปโหลดหลักฐานจริงจากใบสมัครเมนเทอร์ ตอนนี้ยังบันทึกเพียงชื่อไฟล์
- หน้าติดตามใบสมัครแบบเต็มที่ผู้สมัครส่งข้อมูลเพิ่มเองได้
- คิวประจำสัปดาห์ การเลื่อนนัดโดยตรง และการแจ้งเตือนทางอีเมลของนัด
- การแก้บัคหน้าจอมือถือที่ยังไม่ระบุอาการ
