# ขั้นตอนคำขอของเจ้าของข้อมูล และเมื่อข้อมูลรั่ว — ใช้ภายในทีม

> ร่าง ณ 3 ตุลาคม 2569 · ตาม พ.ร.บ.คุ้มครองข้อมูลส่วนบุคคล พ.ศ. 2562 (PDPA) · ต้องให้นักกฎหมายตรวจ

## รับคำขอ

ช่องทาง: อีเมล `[privacy@…]` (ตั้งก่อนเผยแพร่นโยบาย) · ต้องตอบภายใน **30 วัน** นับจากวันที่ได้รับคำขอ

1. **ยืนยันตัวตนก่อนทำอะไร** ขอให้ส่งคำขอจากอีเมลที่ผูกกับบัญชี ถ้าส่งจากอีเมลอื่น ให้ตอบกลับไปที่อีเมลของบัญชีเพื่อยืนยัน ห้ามส่งข้อมูลของใครให้คนที่ยืนยันตัวไม่ได้
2. บันทึกคำขอ: วันที่ได้รับ ผู้ขอ ประเภทคำขอ ผู้รับผิดชอบ วันที่ตอบ (เก็บไว้ในตารางของทีม)

## ประเภทคำขอและวิธีทำ

| สิทธิ | ทำอย่างไร (ตอนนี้ทำด้วยมือในฐานข้อมูล) |
|---|---|
| ขอเข้าถึง/ขอรับสำเนา | ดึงข้อมูลทุกตารางที่มี `user_id` / อีเมลของผู้ขอ (ดูรายการใน data-inventory.md) ส่งเป็นไฟล์ JSON หรือ CSV ⏳ ทำปุ่มส่งออกข้อมูล |
| ขอแก้ไข | ผู้ใช้แก้โปรไฟล์ อีเมล รหัสผ่านได้เองในหน้าแก้โปรไฟล์ ส่วนอื่นทีมงานแก้ให้ |
| ขอลบ / ขอเพิกถอนความยินยอม | ลบบัญชีใน `users` (ข้อมูลที่ผูกจะลบตาม cascade) · เมนเทอร์: ลบช่องทางติดต่อ และซ่อนโปรไฟล์ · รีวิวของผู้ขอ: ลบ · ยกเว้นข้อมูลที่ต้องเก็บตามกฎหมาย ⏳ ปุ่มลบบัญชี |
| ขอคัดค้าน/ขอระงับการใช้ | ระงับบัญชีหรือซ่อนข้อมูลจากหน้าสาธารณะจนกว่าจะตรวจเสร็จ |
| ขอโอนย้ายข้อมูล | เหมือนขอรับสำเนา ในรูปแบบที่อ่านด้วยเครื่องได้ (JSON) |

ถ้าปฏิเสธคำขอ ต้องบอกเหตุผลเป็นลายลักษณ์อักษร และบันทึกไว้

## เมื่อข้อมูลรั่ว

1. **หยุดการรั่วทันที** เช่น เปลี่ยนรหัสฐานข้อมูล Neon, เปลี่ยนคีย์ใน Vercel (`RESEND_API_KEY`, `PAYOUT_ENCRYPTION_KEY`, `CRON_SECRET`, Google), ตัด session ทั้งหมด (`delete from sessions`)
2. **ประเมินภายใน 24 ชั่วโมง** ข้อมูลอะไร ของใคร กี่คน เสี่ยงแค่ไหน
3. **แจ้งสำนักงานคณะกรรมการคุ้มครองข้อมูลส่วนบุคคล (สคส.) ภายใน 72 ชั่วโมง** นับจากที่รู้ เว้นแต่ไม่มีความเสี่ยงต่อสิทธิเสรีภาพของบุคคล (มาตรา 37(4))
4. **ถ้าเสี่ยงสูง แจ้งเจ้าของข้อมูลโดยไม่ชักช้า** พร้อมสิ่งที่ควรทำ (เช่น เปลี่ยนรหัสผ่าน)
5. บันทึกเหตุการณ์ สาเหตุ และสิ่งที่แก้ เก็บไว้
